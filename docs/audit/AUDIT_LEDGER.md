# PoliSim — the gameplay audit: the ledger

The findings of the gameplay audit (`docs/audit/AUDIT_PROTOCOL.md`, ruled by Elias 2026-10-13, `COMPLETED.md` §803), one row per finding. Like `COMPLETED.md`, this is a dated record: each row says what a run measured on its day, with its run id, and a later change to the code does not make a row wrong - a row is closed by the commit that fixes it, or by Elias's word.

**How to read a row.**
- **ID**: `GA-<area>-<n>`; the area is the protocol's numbered area (`GA-0-` for the inventory, `GA-1-` save/load and determinism, ... `GA-12-` the exploit sweep).
- **Variant**: country · start · role · seed · tick (the in-game date, and the day count from the start).
- **Type**: bug · spec · record · board · exploit · unspecified (present in code, named by no spec, row or §).
- **Severity**: S1 crash, softlock, save corruption, NaN · S2 a wrong number on a money path, or a wrong election or office result · S3 a discrepancy a player would notice · S4 text and polish.
- **Expected**: what should happen, and its authority (a §, a ruling, a board, a source).
- **Actual**: what happened, and its evidence (the run id under `PoliSim-captures/logs/audit/`, the log line, the capture).
- **Repro**: the command that reproduces it. Every S1 and S2 is reproduced from its seed twice before it is filed; a visual finding stays "film-observed" until Elias sees it in the Editor; no row rests on a shell probe alone (R-T2).
- **Decision**: none (a clear bug: code contradicting its own spec, no constant or model change) · Elias · architect (a modelling, sourcing or ruling question - collected in `docs/audit/AUDIT_FOR_ARCHITECT.md`, not asked of Elias).
- **Status**: open · fix (Elias's mark) · fixed `<commit>` · parked (its question unanswered) · closed (Elias's word).
