# THE CLAIM CONVENTION — ruled 2026-09-01, governs every document AND every source comment

⚠ **This is the head of the governing document because it outranks everything below it.** It was ruled on
the measurement in `COMPLETED.md` §190: **1,009 of 6,209 live claim-lines asserted a fact about
the code, and 557 asserted nothing else.** Six of those were demonstrably false at the moment they were
measured, and **not one was catchable by any of the checks in the bar.**

## The test

> **The code can change freely and no document becomes wrong** — only *incomplete*, and only where
> TRACKING has genuinely moved.

## Every claim is one of three things

- **INSTRUCTION** — what to do, what is ruled, what is owed. Timeless; never stale.
- **TRACKING** — what is open, whose it is, what it unblocks. Stale only when the work moves.
- **DERIVED** — a fact about the code or the environment: a type or member name, a line number, a count, a
  measured figure, a commit hash, a file path, a build status, a *"there are N of X"*.

## A DERIVED claim has exactly three permitted destinations

1. **GENERATED** — emitted by a tool into a marked block, re-derivable by one command, so it cannot be
   wrong.
2. **REFERENCED** — a pointer to **where the fact lives**, never a transcription. *"the party count is
   whatever `BuildParties()` seeds"*, never *"53 parties"*.
3. **DELETED** — it was decoration. **Most counts in prose are.**

## ⚠ Nobody transcribes, anywhere, in any file

**Not a count. Not a line number. Not a file path. Not a status. Not an environment fact.**

⚠ **This binds SOURCE COMMENTS exactly as it binds markdown, and the proof is that the worst instance was
in code:** `CheckSuite.cs` opened its enumeration comment with *"TWENTY-ONE"* while `Suite` held
twenty-five — and `POLISIM_FEATURE_LIST.md`, a document, had the number right. **Coupling is a property of
transcribed numbers, not of markdown.** The fix for such a comment is a **reference or a generated block —
never writing today's number in place of yesterday's.**

⚠ **An assertion about the environment that is not computed from the environment is forbidden outright.**
It is the class this convention exists to end — and ⚠ **the worked example is this paragraph, which asserted
one and was wrong.**

It read: *"`ERRANDS.md`'s glance instruction asserted the working copy is LF when it was CRLF."* **The
working copy is LF.** Measured `tr -cd '\r' | wc -c` per file: **zero carriage returns, everywhere.** The
review that produced the claim had probed with `grep -c $'\r'`, an empty pattern that matches every line,
and read a count equal to the file's line count as evidence of CRLF. `core.autocrlf=true` is real but
governs a **fresh checkout**, not this tree.

⚠ **So the instruction was RIGHT and the review was wrong, and the correction came within one edit of
flipping a correct statement — which is the exact failure the last line of this section forbids.** The
fault was never the value: it is that **a line ending was written down at all instead of being computed
where it is used.** A true transcription and a false one fail identically the day the environment moves.
**Derive it at the moment it is used, or say nothing about it.**

## Where generated blocks go

The shape is the one `ElectionsDataCatalogGenerator` and `GeneratedCatalogCheck` already prove, unchanged:

```
<!-- GENERATED by <Tool>. DO NOT EDIT BY HAND. source-digest: <sha256> -->
… emitted lines …
<!-- END GENERATED -->
```

Three properties, all load-bearing: a **DO NOT EDIT** stamp, a **digest of the source**, and **drift
detected by comparing the digest, never by re-parsing** — a second parser is a second thing to keep true.

## How a session updates a record without transcribing a fact

- Move a row's **state**; never restate the evidence. `✅ CLOSED at <hash>` is a pointer, not a figure.
- **Re-derive a board; never edit it forward** (the standing rule). ⚠ The roadmap's document table was
  neither re-derived nor edited — it was simply left, and it went silently wrong.
- When a figure is genuinely wanted in prose, **name the command that produces it** instead of its result.
- ⚠ **Never repair a stale fact by flipping it.** Derive it or delete it.

## The process rules — ruled standing 2026-09-01

⚠ **These are not carelessness to be fixed by care.** Each was bought by measured, repeated loss, and the
measurement is `COMPLETED.md` §190 §B.3.

- ⚠ **NO SHELL STATE ACROSS TOOL CALLS.** Every invocation is complete in itself: no variable set in one
  call and read in another, no reliance on a working directory, no chaining a cleanup to a run where a
  short-circuit can skip the run while reporting success.
- ⚠ **EVERY FILE EDIT IS ONE SELF-CONTAINED OPERATION, MATCHED ON TEXT — never on a line number or a
  walked position.** A walk-back that never matches runs to the top of the file.
- ⚠ **Prefer a direct file write to a shell heredoc for anything containing prose.** *(This rule caught
  its own twenty-fifth instance inside the review that proposed it: the report died on broken quoting as a
  heredoc and succeeded as a file write.)*
- ⚠ **ONE GREEN BAR PER COMMIT, NO EXCEPTIONS** — green for the tree being committed, not "green when I
  last looked". **Precondition, and it is why this rule gets skipped: the bar CANNOT run while the Unity
  Editor is open** — Unity refuses a second instance on the same project. A bar run means the Editor is
  closed first.
- ⚠ **The dominant failure mode is that a wrong invocation and a right one look identical in their
  output.** A bar can pass in seconds having run nothing; a capture can exit 0 having filmed the wrong
  screen. **Check what a run actually did, never that it merely exited.**

## Standing constraints — rules that bind every pass, not tasks

- **Numbering is stable.** Master Sequence items and Steps are cited throughout the record and the code;
  **never renumber.** ⚠ Two distinct items carry "9" — disambiguate by name when citing, never by number.
- ⚠ **THE CRITICAL CORRECTNESS RISK — published vs live.** The player-facing UI reads the **PUBLISHED**
  (lagged, possibly-revised) series; every internal system keeps reading **LIVE** values. A leak makes the
  model consume its own stale output, and **the effect may not appear for hundreds of turns.** The
  enforcement is the one-directional rule: `PublicationSystem` writes `Country.Published` and reads
  `Country.State`, **never the reverse.**
- **`[GAP]` figures are Elias's to source, never to invent.** The variant-axis rule governs any
  re-sourcing.
- **Calibration stays at turns 100–200; the long horizon is a diagnostic, never a target.** Judge a fix by
  whether the mechanism is present and correctly signed. ⚠ **The word "equilibrium" stays banned without a
  run that earns it.**
- ⚠ **SCREEN GRANULARITY, NEVER ELEMENT GRANULARITY.** IMGUI composites as one flat rectangle and no
  Canvas render mode draws above it; a screen is either Canvas or IMGUI, **never both interleaved.** Any
  request that violates this silently **is a request to migrate that screen wholesale to Canvas**, and
  should be recognised as such rather than hacked around.
- **Spec references:** anything row-shaped cites `COMPLETED.md` §187 by section. ⚠ **Every number
  that spec supplies is suspect until derived or explicitly confirmed** — its own banner says so.
  **Declare deviations from the boards rather than diverging silently.**
- **One row type per capture for NEW row types, never batched** — a re-capture of an already-shipped row
  may batch. The rule exists to catch first-build defects.
- **The guard scopes are fixed:** `UiOverflowGuard` (does text fit its rect) · `UiContainmentGuard` (does a
  child rect sit inside its container) · `ScreenEdgeCheck` (pixel lines per PNG, flushness not magnitude,
  at the captured resolutions only). ⚠ **Do not build a third site-specific guard** — a GUILayout-aware
  check needs IMGUI internals; the pixel check is cheaper, exists, and asks the question the player
  experiences.

## Rules learned from consolidating the documents four times

*The instances that taught these are in `COMPLETED.md` §181 and the sections it points at. The lessons are
here; the evidence is there.*

- **Verify against the repo and the commit history, not against a summary.** A summary is exactly where a
  false "DONE" hides.
- **Check callers before believing a feature exists.** Code has shipped with zero callers more than once.
  `grep` for the call sites; do not assume the wiring landed with the code.
- **If removing finished items empties a document, delete it.** An empty shell drifts back into use.
- ⚠ **Do not duplicate a live list into another document.** Two copies of one list is the drift these
  passes exist to undo — and the roadmap was retired partly because its trigger shelf duplicated
  `COMPLETED.md` §197 §5.
- **Repoint references before deleting a file, and grep afterwards to prove nothing dangles** — source
  comments included.
- ⚠ **A document can assert two states of one task at once.** When a live document is edited, search it
  for the task's other mentions before saving.
