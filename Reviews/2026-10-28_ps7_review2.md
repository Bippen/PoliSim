## New findings

### N1 (High) - ChamberVerdictCacheCheck's who-governs guard fails on SimulationManager.Italy.cs:119-121
`ProjectMandates` writes `projection.PmParty = granted.Camera.PmParty;`, `projection.Cabinet.Add(key)` and `projection.Support.Add(key)`. The guard's DirectWrite regex matches all three (receiver `projection`). The `projection` exemption is file-scoped: it applies only to `/Simulation/SimulationManager.FormationProjection.cs` (s918). So each line adds a failure: "writes who governs in place outside GovernmentRecord's methods". This is the same class as H1, and the bar goes red. Nothing is actually wrong at runtime, because a FormationProjection is not a record. Fix: build the expected government through `ExpectNamed` (and the view through `ProjectedView`, see N3) inside FormationProjection.cs, or move ProjectMandates into that file. Do not widen the guard's exemption by name.

### N2 (High) - FormationProjectionDiagnostic goes red on Italy
- (a) Check (1), which existed before the fix round but is still red on this branch: the loop over every CountryId now reaches Italy. TryPredictShares answers, Run returns ItalyRosatellum, and CountsParliament is true. But `procedure` is set only from `RoundsApply` or `SejmStepsApply`, both false for Italy, so Italy is listed as an orphan ("NONE FOR Italy"). Add `m.ItalianMandatesApply(c) ? "the President's mandates"`.
- (b) The fix round added Italy to the (2)-(3) loop but gave it no branch of its own:
  - "The board's view is the projection's" requires `view.ProjectionStep != null` when a government is expected. ProjectMandates hands `granted.View` (a GovernmentFormation.View from Describe), whose ProjectionStep is null. The check fails whenever a mandate is projected to succeed.
  - "(3) one code" then calls `OpenSpeakerRound` for Italy and compares the round's order, first asked and first draft with the projection's. ProjectMandates fills none of these, so `p.Order` is empty and `p.FirstAsked` is null. If SpeakerOrder returns an order, the comparison fails. If it returns none, `draft != null` fails. Either way the check fails on every run.
  
  Fix: give Italy a branch like Poland's that asserts what the mandates project (Expected implies a cabinet, a PM party and a step; otherwise a Reason, and a view carrying ProjectionStep), then `continue` before (3).

### N3 (Medium) - the night board gets the mandate's raw formation view, not a projection view

2. **AdvanceItalianMandates fires exactly once.**
   - "Done" is derived from saved state:
     - FormedOn after the count (a granted mandate);
     - Caretaker with CaretakerSince on or after the sitting (Discharge always resets CaretakerSince, including for the already-caretaker Draghi);
     - or an order on or after the sitting.
   - FormedOn, Caretaker, CaretakerSince, ElectionHistory and the extra-election fields are all saved, so a load neither re-fires nor loses it.
   - It never fires before the game's own first count: no seeded ElectionHistory exists.
   - A first sitting inside the semestre bianco: the mandates run. If all fail, the caretaker is discharged on the sitting (so no re-fire), and the extra election is dated from the term's end. No further mandate is tried meanwhile (declared, K208).

6. **GameController.ItalianVerdict:**
   - No hand-built possessive and no banned token. "DERIVED" appears only in the Sejm precedent's exact wording. Camera/Senato are single-hump words, not CamelCase identifiers.
   - Lengths are comparable to the Sejm verdict's, in the same wrapped field.
   - The meta's guid is unique.
