## (1) q20 - one formation code

### Reuse, function by function (all hold)
- **The round's opening** (`ProjectRound`, FormationProjection.cs:49-57) is built field by field as `OpenSpeakerRound` builds it for `OpenRoundAfterElection` (SimulationManager.cs:4782-4786, :5614):
  - `ReadsOn = pollingDay` and `Vintage = WorldClock.VintageOfElection(id, pollingDay)`;
  - no refusals, because §641 ends them at the election;
  - for the Bundestag, `Convenes` and `Phase = 1`.
  - `RoundLines` on no refusals is an empty list (`GovernmentFormation.RefusalLines`, :388-391), so the night's separate `SpeakerOrder(country, electionReading)` (GameController.cs:6522, with no lines) gives the same order as the projection.
- **The ask sequence.** `SpeakerRound.Turn` starts at -1 and `AskNext` increments before it indexes, so the procedure asks `Order[0]`, `Order[1]`, and so on. The projection's `asks % Count` does the same.
  - A rejection advances the turn in both.
  - A decline that tables nothing advances the turn with no rejection in both (`AnswerOfferNow`, :5720-5722, against FormationProjection.cs:93-97).
  - `round.Declines` persists across later asks in both, so a re-asked formateur drafts without the player in both (`DraftProposal`, :4737).
- **The answer to a wait.** This is K49's rule from `AnswerWaitsAsTheAi` (PlayerElection.cs:61-70).
  - The player asked: `DraftProposal`, then the vote.
  - An offer: `Formateur.Answer(..., null)`. If every party accepts, the offer is accepted. If not, the player declines, the proposal is redrafted, and it is tabled only on `Passes` for the Riksdag, or on `AllAccept && Investiture != null && !SplitsJointGroup` for the Bundestag.
  - FormationProjection.cs:85-99 uses the same expressions with the same `playersParty` arguments: null for the offer, `player` for the redraft.
- **The investiture.** `Formateur.Answer(..., player)` at FormationProjection.cs:105 is `Investiture`'s call (:4939). Supporters are read as `Install` reads them (:5551, against FormationProjection.cs:212), and `PmParty = proposal.Formateur` as `FromProposal` sets it (GovernmentRecord.cs:305).
- **The Bundestag's first ballot** (`FirstBallot`, FormationProjection.cs:123-151) is `PersonBallot`'s phase 1 (:4996-5035) in the same order: `Commitments` (on `round.Proposal`), the candidates `{Formateur}`, `Tally`, `MajorityOf`, then `ElectedGovernment(leader, tabled)`.
  - `ElectedGovernment` and `GroupAlone` write only `round.Declines` (added and removed again) and `round.Log`, and both belong to the projection's private round.
- **The Sejm** (`ProjectSejm`, FormationProjection.cs:153-205) walks `SejmStep` in its order (Sejm.cs:46-135):
  - the record's designee if `TryOfRecord` and `TryGovernmentAt(record.Appointed)` hold, else `Projection`;
  - then `SejmFormation.Carries`;
  - if refused, `TryRecordCabinet`, else `Projection` with `Carries`.
- **0f0cc3cb's `Installed`** (FormationProjection.cs:226-240) is the install's own rule:
  - `SameCabinet`'s condition (`g.PmParty == pm && SameKeys`, Sejm.cs:190) gives the reappointed outgoing record, as `Reappoint` keeps it (Sejm.cs:78);
  - otherwise `InstallSejmCabinet`'s view match (Sejm.cs:151-156) gives `FromView` on the install day, or the cabinet as named (`OfNamedCabinet`, :160).
  - The dates match: `record.Appointed`, or `sitting + StepWindowDays`, which is when `Designated` runs; `record.SejmAppointed` for the record's cabinet.
- **The `Projection` call-through, the same expression.** Before, `Projection(country, f)` was `GovernmentFormation.ViewOf(country, DeclarationReading.OfElection(country.Id, f.PollingDay))`. Now it is `Projection(country, f.PollingDay)`, whose body is `GovernmentFormation.ViewOf(country, DeclarationReading.OfElection(country.Id, pollingDay))` (Sejm.cs:141-145). It is one static, pure expression with the same argument, so it is byte-identical for every `SejmStep` and `InstallSejmCabinet` caller.

### The spread of the excess (holds, one edge)
`Hold` (EntrantLayer.cs:198-226) caps each created party, adds the excess to `room` (the sum of the non-created shares), and gives each non-created party `excess * held[i] / room`. The sum is preserved exactly up to float rounding. Created parties under their cap receive nothing. **Edge (L6):** when `room <= 0` (every key is created), it returns `held` without renormalising (:223). No roster can reach that.

### The Regional party in its own valkrets
- `available[p]` is set to true only in the party's valkrets (SwedishRegions.cs:78), which is the CSU's rule. Real parties' availability is untouched.
- Real parties' **regional** shares do change once a Regional party exists: its national share is concentrated in one valkrets, so the others are reshaped there and elsewhere. That is the ruling's intent. With none registered, nothing changes.
- `ElectionDay`'s scaled noise (`sqrt(s(1-s))`) keeps a zero share at zero, so the party stays at 0 outside its region in the count too.
- CreatedPartyReachDiagnostic (4) checks that the rebuilt share equals the national share to 1e-9, which is good teeth.
