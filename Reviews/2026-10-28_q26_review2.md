**M1 (Sweden's surplus half) - ANSWERED IN FORM, but it introduces a price cliff (see N1).**
- *Same treatment as ClearBlock?* Formally yes. ClearBlock (248-253) prices a residual at or below zero at `curtailmentOffer` and books it as `CurtailedMw`. ClearSweden now books a national balance above the seed's as `ChainCurtailedMw` and prices SE4 at `CurtailmentOffer`, along with every zone back to the first binding link. Sweden offers nothing flexible (fossil not dispatched, hydro fixed in MustRun), so ClearBlock applied to such a country would do the same. The effect is not the same, though. For the other five, the curtailment price arrives only when must-run covers all demand. Sweden's reference sits exactly at the seed balance, so Sweden sits on a knife-edge: one MW below is the ceiling, one MW above is the floor.
- *Seed exactly zero both ways?* Yes. `gap = seedUnbalance[b] - ChainUnbalanceMw[b]` is x - x = +0.0 on the record's fleet, because the reference is the same doubles by the same code at ProbeLinkCapacityScale 1, and the balance reads no price, water value or deficit share. Neither `> 0` nor `< 0` fires. `NuclearAvailability` is constant. No path places orders in the default trajectory: AiEnergyMinistry `Live = false`, and `FleetOrders` is null at the seed. **The default dump does not move.** EnergyLayerCheck 261 and ReservoirDispatchDiagnostic 50 already pin the seed prices to the exchange's, so a curtailment at the seed would also turn those red.
- *Money, CO2, ledger.* `ChainCurtailedMw` is read only by the invariant. Like `BlockResult.CurtailedMw` for every country, it reaches money only through the price. `Accumulate` counts must-run gross (449-453) before the curtailment is known, for Sweden and for ClearBlock countries alike, so the annual GWh treat curtailed energy consistently, and that energy carries zero CO2. Sweden dispatches no fossil, so CO2 does not move. The ledger reads the price through `LoadWeightedPricePerMwh`. That is the consistent path, and it is the one N1 is about.
- *The invariant (AuditInvariants.cs 415-423).* The reading is algebraically right but now **vacuous**. The block is reached only when no link binds (408). There, gap>0 gives `net = c + (s - c) = s`, gap<0 gives `net = c - (c - s) = s`, and gap 0 gives `net = c = s`. So `net` is always the seed residual, -24.2 / -5.0 / +32.4 MW in my replica, and `|net| > 500` can never fire. It no longer hides genuine unbalance, because the q27 rule now books all of it. But it no longer tests anything either (see N2).

## New findings

**N1 (High) - One build step anywhere in Sweden prices the whole country at the curtailment offer, all year.** `EnergyMarket.cs` 591-595. The reference is the seed's own balance, so any MW of must-run above the record (wind, solar or nuclear; `EnergyFleet.Scale > 1`) makes `gap < 0`. In my replica of the generated rows, no Swedish link binds at the seed: flows of about 600 / 3200 / 3400 MW against NTCs of 3300 / 7300 / 5600. It still binds in none with 5 % more wind (the diagnostic's own case). So the loop `for z = n-1 .. 0` sets **all four zones** to `CurtailmentOffer` (0 EUR/MWh) in every block. Failure scenario: the player presses + once on Sweden's wind tile (`StepMw`, 1 % of the fleet, several hundred MW). When the order lands, the chain sits about 50-125 MW above the seed and Sweden's load-weighted wholesale price falls from the exchange's 2023 level to 0. It stays there for every later year. The fall reaches `EnergyLedger` (265, 367: `WholesalePerKwh`), and through that every class's bill and the bills' confidence channel. The congestion rent goes to 0 (all price differences vanish). GA-6-2's `p6_se_m_build` moves from "prices unchanged" to "prices zero", which is worse. Before the rework the price stayed at `own[z]`. The knife-edge is the problem, not curtailment as such. Sweden's marginal resource in the model is reservoir hydro at the water value (`own[z]` is built from it), and surplus must-run displaces stored water before anything spills. A defensible reading keeps `ChainCurtailedMw` (or "displaced hydro") and leaves the price at `own[z]` until a spill condition, or else declares the cliff as a K-line for Elias. Either way the diagnostic's `floor` assertion in (e) currently locks the cliff in. The first review's M1 invited "price the surplus at the chain's end", so this is partly the reviewer's prescription. But the consequence for a single step was not weighed, and it is a player-visible economic jump from the smallest press the page offers.

**N2 (Low) - The unbalance invariant can no longer fire.** `AuditInvariants.cs` 418-419. Where no link binds, `net` equals `SwedenSeedUnbalanceMw()[b]` identically (|seed| <= 32.4 MW), so the 500 MW bound is dead code. A broken booking, for example `ChainCurtailedMw` written with the wrong sign or not written, would not be caught. Failure scenario: a later edit sets `ChainCurtailedMw[b] = gap` (negative). Then `net = c - gap = 2c - s`, which reaches 500 only for a surplus of more than about 235 MW. Smaller errors pass silently. Suggestion: breach on `|net - seed[b]| > 1e-6 x max(1, |seed[b]|)`, which is the identity, and keep a separate bound on `|seed|`.
