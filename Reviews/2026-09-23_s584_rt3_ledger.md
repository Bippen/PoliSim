## PART 1 findings, ranked

### P1-1 HIGH: the exemption accepts real code changes in 4 shape families (10 concrete cases, all ACCEPTED by the check's own code)

The exemption trusts `Code(before) == Code(after)` after `SourceText.WithoutComments`. `SourceText.cs`'s block rule `/\*.*?\*/` (Singleline) and its "strip from `//` when the line has no `"`" rule mis-strip the shapes below, and `MisStripShape` (`ReviewLedgerCheck.cs:267-282`) does not refuse any of them.

**(a) Quote parity miscounted by `\"` or a `'"'` char literal** (`ReviewLedgerCheck.cs:278-279`, which counts raw `"` characters). The opener sits inside a string literal but the count before it is even, and the match holds no `"`. So the block inside the literal is stripped on both sides and the literal's content change is invisible:
- `string s = "a\"b /* one */ c";` -> `string s = "a\"b /* two */ c";` **ACCEPTED** (string value changes)
- `char q = '"'; string s = "x /* one */ y";` -> `... /* two */ ...` **ACCEPTED**
- `char q = '\"'; string s = "x /* one */ y";` -> `... /* two */ ...` **ACCEPTED**
- `string s = "\"" + "a /* one */ b";` -> `... /* two */ ...` **ACCEPTED**
- `string s = $"{'"'} /* one */";` -> `... /* two */ ...` **ACCEPTED**

**(b) Verbatim-interpolated strings across lines whose first line's hole holds a quote.** `VerbatimAcrossLines` (`ReviewLedgerCheck.cs:264`, `(?:@\$?|\$@)"(?:[^"]|"")*\n`) stops at the first lone `"`, and a hole such as `{F("a")}` or `{'"'}` supplies one. The string's later lines then pass through the line rule (no quote on them), so `//` text and `/* */` text inside the literal are stripped as comments:
- `var q = $@"{Col("rate")}` / `// rate = 0.25` / `";` -> `// rate = 0.35` **ACCEPTED** (literal content changes)
- `string s = @$"{'"'}` / `// one` / `";` -> `// two` **ACCEPTED**
- `string s = $@"{F("a")}` / `x /* one */ y` / `";` -> `/* two */` **ACCEPTED**
- Blank lines and trailing whitespace inside such a string are also dropped by `Code()`, so whitespace edits to the literal are accepted too.

**(c) A block opener inside a preprocessor-skipped section.** The compiler does not lex a skipped `#if` section (only directives are recognised), but the regex does. Before and after:
```
#if false
/* disabled
#endif
paid = 1;      // -> paid = 2;
// */
```
`paid = 1;` is LIVE code (`Skip.cs` compiled and printed `paid=1`). The regex block swallows it: no `"`, no `//` before the opener, even quote count. The change is **ACCEPTED**. Any `#if UNITY_EDITOR` / `#if !X` section does the same in one build configuration.

**Exposure today.** It is latent. A grep of all 34 money-path files finds no `\"` before a `/*`, no `'"'`, no `@"`/`$@"`/`@$"`, and no `#if`. But each hole needs only ONE reviewed state that contains the shape: a reviewer sees an innocent literal or directive. After that, every later edit inside it inherits the review forever. The guard's promise is exactly that this cannot happen, and `ProbeCommentOnly` prints "every mis-strip shape owed".

**Fix.** Either replace the shape blacklist with a real ~80-line C# comment lexer, or refuse more shapes:
- The lexer handles `"..."` with `\` escapes, `'...'` char literals with escapes, `@"..."` with `""`, and `$"`/`$@"`/`@$"` with brace-depth holes that may nest literals. It refuses `"""` and any `#if/#elif/#else`. It compares the token streams without comments.
- The minimal alternative, in `MisStripShape`: refuse when a block match's line contains `\"`, `'"'` or `'\"'`; refuse any text containing `$@"` or `@$"`; refuse any text containing a `#if`/`#elif`/`#else` directive.
- Either way, add the ten cases above to `ProbeCommentOnly`. It has 13 cases and none of these.

### P1-2 MEDIUM: grandfathered anchors deadlock the history pass

Grandfathered rows anchor the walk in BOTH passes (`CoveredThroughComments` checks `grandfathered.ContainsKey(id)`). But only the STATE pass keeps an anchor alive (`ReviewLedgerCheck.cs:142`), and the STALE test (`:151`) runs before the history pass. The sequence:
1. File F is grandfathered at G. Commit c1 (after `GuardedSince`) edits only comments, giving state S1. Both passes accept it via G.
2. Commit c2 changes code, giving S2, and gets its `reviewed` row. G is now not live, so the check fails with "STALE grandfathered row ... remove the row".
3. The author removes G, as told. The history pass then walks c1's blob S1 back to G's state, finds no row, and fails on the next step: **"NO REVIEW ON RECORD: commit c1"**.

The bar is red with no remedy except a retroactive review of a past state. Keeping G gives STALE; removing G gives NO REVIEW. There is also a smaller incoherence: a commit that lands EXACTLY on a grandfathered state fails the history pass (it checks only `reviewed`, `:181`), while its comment-edited sibling passes.

**Fix (pick one).**
- (i) Inherit only from `reviewed` rows: pass an empty grandfathered set into `CoveredThroughComments`. A grandfathered file's first edit of any kind then owes its review, which is the ratchet's intent.
- (ii) Make the inheritance explicit: a `comment-only` ledger row (kind file, anchor sha in the note). The check re-proves it with `CommentOnlyRefusal` between the two blobs, so the claim survives the anchor row's removal.

### P1-3 MEDIUM (policy): a comment-only edit can change what a constant claims to be

`ConstantProvenanceCheck` reads the provenance mark (`SOURCED`/`[AUTHORED-DRAFT]`/`DERIVED`/`CONVENTION`) from the COMMENT above each simulation constant. Its own doc names review as the thing that caught `[AUTHORED-DRAFT]` values drifting into being cited as measurements (C-C14, C-D2). Under the exemption, relabelling `[AUTHORED-DRAFT]` as `SOURCED: <anything>` on a money-path constant needs no review, and both checks stay green. The same applies to unit comments ("nominal", "real") that the R-T3 rule itself relies on.

**Fix.** Refuse the exemption when any comment line containing a provenance mark, or a digit, differs between the two sides. Compare the multiset of such comment lines.

### P1 (b)/(c): the git walk is SOUND
Every step compares `current` against the previous distinct blob it actually read. Code-equality is transitive, and the anchor id is keyed on the same path. So whatever commit `git log -1 <rev> -- path` returns (merges, simplification, first-parent `^`), a wrong pick can only cause a false refusal, never a false acceptance. `log.follow` is not set in this repo, so there is no rename following. `core.autocrlf=true` is neutralised by `\r` removal. A rename, a deletion, a root commit or a shallow boundary all return null (owed). The state pass cannot skip intermediate commits: each step is compared. ### S2-1 HIGH: newline characters the stripper does not recognise (4 accepted code changes)
C# ends a `//` comment at CR, LF, U+0085, U+2028 and U+2029. `Code()` deletes every `\r` (`text.Replace("\r", "")`), and `WithoutComments` splits only on `\n`. So live code that follows a lone CR, NEL, LS or PS on a `//` line is stripped as comment.
- `int paid = 0; // note\rpaid = 1;` changed to `paid = 2` is **ACCEPTED**. The same holds with `\u0085`, ` ` and ` `.
- ⚠ **The lone CR also breaks the ledger's state identity itself.** This is pre-existing since §546, not introduced by s584. `Sha256NoCr` drops every `0x0D` byte. So a reviewed file holding the comment `// was: paid = 2;` and an edited file holding `// was: \rpaid = 2;` have the SAME digest. The state pass then reports "in a reviewed state" for a file that now runs `paid = 2;`, with no walk and no exemption involved. git (`autocrlf=true`) keeps a lone CR unchanged.
- **Fix:**
  - In `Sha256NoCr`, strip a CR only when it precedes an LF (CRLF becomes LF), not every CR.
  - In `MisStripShape`, refuse any text containing a lone `\r` (one not followed by `\n`), `\u0085`, ` ` or ` `.
  - Consider failing the bar on these characters in any money path, since no legitimate source needs them.

### S2-2 HIGH: directives whose rest-of-line the compiler does not lex (2 accepted)
`#region`/`#endregion` names and `#warning`/`#error` messages are plain message text to the compiler, so a `/*` there is not a comment. The block regex still opens on it and swallows the live code up to a later `*/`.
- `#region Rates /* note` / `paid = 1;` / `// */` / `#endregion` changed to `paid = 2` is **ACCEPTED**. `#region` is common in C#.
- `#warning w /* note` / `paid = 1;` / `// */` is **ACCEPTED**. It compiles with only the CS1030 warning.
- **Fix:** refuse a block match whose start line is a directive line of any kind (`^\s*#`).

### S2-3 MEDIUM: `PreprocessorBranch` misses legal directive whitespace and the BOM (3 accepted)
`^[ \t]*#[ \t]*(if|elif|else)\b` only knows space and tab.
- C# also allows vertical tab, form feed and every Unicode Zs character (NBSP, U+2000-U+200A, U+3000 and others) before `#`.
- A UTF-8 BOM decodes to U+FEFF at the start of line 1 (`Encoding.UTF8.GetString` keeps it). So a file that OPENS with `#if` is not refused. That is the common Unity shape: `#if UNITY_EDITOR` at the top of a file saved with a BOM.

Accepted cases:
- ` #if false` / `/* x` / `#endif` / `paid = 1;` / `// */` is **ACCEPTED**.
- The same shape with `\v` is **ACCEPTED**.
- The same shape with `﻿#if false` on line 1 is **ACCEPTED**.

Covered: `# if` with spaces (N13) is owed, and `#elif` inside a block (N14) is owed, which is only over-refusal.

**Fix:** allow any whitespace, Zs character or a leading U+FEFF before the `#`, excluding newlines. Alternatively, drop a leading U+FEFF and test whether `line.TrimStart()` starts with `#`.

### S2-4 MEDIUM: P1-3's sorted multiset lets provenance lines SWAP between constants (1 accepted)

- Before: `// SOURCED: OECD 2023, table 4` above `const float A = 0.5f;`, and `// [AUTHORED-DRAFT] a game figure` above `const float B = 0.7f;`.
