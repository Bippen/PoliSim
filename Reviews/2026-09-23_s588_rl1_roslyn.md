# Review: RL-1 - the review ledger's comment-only verdict on Roslyn (2026-09-23, s588)

**What was reviewed.** The RL-1 change: `Tools/textcheck/CommentOnly.cs` (Microsoft.CodeAnalysis.CSharp: both texts parsed, comment and whitespace trivia dropped, the rest compared token for token, directives and disabled text kept), the runner's `commentonly` mode (`Tools/textcheck/Runner.cs`), `Tools/textcheck/TextCheck.csproj` (the package reference; the file tracked for the first time), and `Assets/Editor/ReviewLedgerCheck.cs` (the regex refusal list removed; the verdict taken from the runner; the probe). It is a GUARD, not a money path and not a baseline - reviewed because the regex version it replaces was broken twice by review (§584).

# RL-1 adversarial review: the comment-only test on Roslyn

**VERDICT: SIGN WITH FIXES.** The Roslyn core in `Tools/textcheck/CommentOnly.cs` held against every lexer-level attack I put to it. I found no before/after pair where the token-and-kept-trivia comparison says ACCEPT for a lexing or parsing reason while the compiled output differs. The false ACCEPTs I did find are all outside the token comparison:

- the provenance pairing in `Assets/Editor/ReviewLedgerCheck.cs` (F1)
- lossy UTF-8 decoding in front of the parser (F2)
- caller-info attributes that turn line numbers or argument source text into constants (F4, latent)

The Unity-side protocol fails closed. `CommentOnlyRefusal` cannot return null unless the runner printed `VERDICT<TAB>000<TAB>ACCEPT` and exited 0 after a `dotnet build` that also exited 0. It does have cost and operational defects (F5 to F8).

Method: I built a scratch harness (`scratchpad/rl1attack/`) that links the repo's `CommentOnly.cs` byte for byte (diffed against the repo copy). For each pair it compiles both texts with Roslyn at LangVersion 9 (Unity's `-langversion:9.0`, read from `Library/Bee/.../Assembly-CSharp.rsp`) and at Latest, runs them, and flags any ACCEPT whose outputs differ. I compiled the encoding case with Unity's own compiler (`Editor/Data/DotNetSdk/sdk/8.0.318/Roslyn/bincore/csc.dll`). I also ran the already-built runner (`PoliSim-captures/textcheck/bin/Release/net8.0/textcheck.dll commentonly <dir>`) on scratch pairs to confirm the output protocol. Nothing in the repository was edited and Unity was not run.

## Findings, ranked

### F1 (MEDIUM, false ACCEPT, confirmed): the provenance guard disagrees with ConstantProvenanceCheck about which constant a mark belongs to

`ProvenanceLines` pairs each marked line with "the next line that is not blank and does not start with `//`, `/*` or `*`". `ConstantProvenanceCheck.CommentBlockAbove` reads something else: only the unbroken run of `//` lines directly above the declaration, plus the declaration line itself. It stops at a blank line or a `/* */` line. So a whitespace-only or comment-only edit can change what the checker says a constant claims, while ProvenanceLines and the parser both see no change.

| pair | parser | ProvenanceLines | ConstantProvenanceCheck reading | result |
|---|---|---|---|---|
| `// SOURCED: OECD\n\nconst float B = 2f;` to `// SOURCED: OECD\nconst float B = 2f;` | same code | SAME | B UNMARKED to B **SOURCED** | **ACCEPT** |
| `// SOURCED: OECD\n/* see note */\nconst float B = 2f;` to the same without the `/* */` line | same code | SAME | B UNMARKED to B **SOURCED** | **ACCEPT** |
| `// SOURCED: OECD\n/* a */ const float A = 1f;\nconst float B = 2f;` to `/* a */ const float A = 1f;\n// SOURCED: OECD\nconst float B = 2f;` | same code | SAME (both give `=> const float B`) | a reviewer sees the mark move from A to B | **ACCEPT** |

The reverse edits (adding a blank line or a `/* */` line) detach a mark silently. `UnmarkedCeiling` only notices if the count crosses the ceiling. The third row is a regression from s584: the old `Code(keepBlank)` kept `const float A` after stripping `/* a */`. The blank-line variant was already open in s584.

**Fix.** Compare provenance the way the checker reads it. Make `ConstantProvenanceCheck.Declaration`, `CommentBlockAbove` and `FindMark` internal. In `CommentOnlyRefusal`, build for each text the ordered list of (declaration line trimmed, `FindMark(CommentBlockAbove(lines, i))`, or the whole context block) and refuse when the two lists differ. Keep the existing "a marked line changed" rule alongside it. Add the three rows above to `ProbeCommentOnly` as OWED.

### F2 (MEDIUM, false ACCEPT, confirmed with Unity's csc): lossy UTF-8 decoding hides a changed literal

`CoveredThroughComments` calls `CommentOnlyRefusal(Encoding.UTF8.GetString(previous), Encoding.UTF8.GetString(current))`. That decoder replaces invalid bytes with U+FFFD. The runner then reads the pair with `new UTF8Encoding(false, false)`, which also replaces. As a result, two blobs that differ only in an invalid byte become the same text.

- Pair: `System.Console.Write((int)"<0xE9>"[0]);` against `...(int)"<0xE8>"[0]);` (Latin-1 bytes, not valid UTF-8).
- Verdict: decoded texts equal, `Refusal == null`, **ACCEPT**. The built runner gives the same result directly (`VERDICT 002 ACCEPT`).
- Compiled: Unity's `Assembly-CSharp.rsp` passes no `/codepage`, so csc falls back to the ANSI code page. The user-string heaps read **U+00E9** and **U+00E8** respectively: different programs.

`MojibakeCheck` (strict UTF-8 over `Assets/**/*.cs`) guards the working tree in the same bar. Nothing guards the history pass, which walks committed blobs.

**Fix.** Do not round-trip through strings. Write the blob bytes straight into the pair files (`File.WriteAllBytes(..., previous)`). In `Runner.CommentOnlyMode`, decode with `new UTF8Encoding(false, true)` and emit `OWED not UTF-8` on `DecoderFallbackException`. Alternatively, decode strictly on the Unity side and refuse there. Add a probe case, which has to be carried as bytes.

### F3 (LOW-MEDIUM, false OWE, latent): CRLF working tree against an LF blob

`core.autocrlf=true`. `git ls-files --eol` shows 14 of the 35 money-path files as `w/crlf` and one (`EnergyLedger.cs`) as `w/mixed`. The state pass always compares the working-tree bytes (`current`) against LF blobs. When `previous` has the same `Sha256NoCr`, no step is taken and `current` stays the CRLF bytes, so this holds even after the comment edit is committed. EOL trivia is dropped, so plain code is fine (verified: ACCEPT). A multi-line verbatim or raw string, or a multi-line disabled `#if` block (every `#if UNITY_EDITOR` block is disabled in a symbol-less parse), carries the line breaks inside a token or a DisabledText trivia. Verified OWED:

- `@"a\nb"` against `@"a\r\nb"`: OWED. Correct as a statement about values (3 against 4 characters), but it contradicts the ledger's own identity, because `Sha256NoCr` already calls them the same state.
- `#if UNITY_EDITOR\n static int a = 1;\n static int b = 2;\n#endif` against the same with CRLF: OWED, an over-refusal.

Today 0 of 35 money files contain `#if`/`#elif`/`#else`, a multi-line verbatim string or `"""`, so this is latent. The first such file would make the exemption unreachable for it, permanently, in the state pass.

**Fix.** Normalise `"\r\n"` to `"\n"` on both sides before the runner (in `CommentOnlyRefusal` or `CoveredThroughComments`). This is no weaker than the digest, which is already CR-blind. Lone CR, NEL, LS and PS stay as they are and the parser handles them correctly. Add a probe case "the same file, CRLF against LF, with a multi-line #if block: accepted".

### F4 (LOW, false ACCEPT, latent: no use today): caller-info attributes turn trivia into constants

- `[CallerLineNumber]`: adding one comment line above a call site gives **4 then 5** in the compiled output (C# 9 and Latest). **ACCEPT**.
- `[CallerArgumentExpression("v")]`: `E(1 /* one */ + 2)` against `E(1 /* two */ + 2)`, and `E(1+2)` against `E(1 + 2)`, both **ACCEPT**. The compiled strings differ. Roslyn 4.11 honours the attribute even at LangVersion 9 when the type exists. Unity's netstandard2.1 does not ship it, but a project can declare it.

I found no `Caller*` attribute under `Assets/` (grep). Only render-pipeline packages declare `CallerLineNumber`, and money paths do not call them. PDB sequence points and stack-trace line numbers also move, which the ruling accepts as inherent.

**Fix.** State this as the residual in the class doc. Add a structural guard: the exemption refuses, or the probe fails, when any `Assets/**/*.cs` declares a parameter with `CallerLineNumber` or `CallerArgumentExpression`.

### F5 (MEDIUM, cost): one `dotnet build` per comparison

`CommentOnlyRefusal` runs `dotnet build` and then the runner on every call. The walk calls it once per step, per file, in both the state pass and the history pass, and the probe adds one more on every run. An up-to-date build of a comparable project measured 2.15 to 2.34 s here, and the runner 0.37 s, so about 2.6 s per step where the regex took microseconds. The bound is 40 steps per walk.

**Fix.** Build at most once per `Run` (a static flag set by the probe's successful build). Cache verdicts by (NoCr sha before, NoCr sha after) across the two passes, since they walk the same pairs. Optionally pre-compute a whole walk's pairs in one runner call.

### F6 (LOW, fail-closed but brittle): the verdict depends on 11 unrelated sources building under shims

`TextCheck.csproj` also compiles `SourceText.cs`, `ResidueCheck.cs`, `PlaySheetGenerator.cs` and others. An edit that compiles in Unity but not under the shims makes `dotnet build` fail. The probe then reports NO VERDICT and the cheap bar goes red for a reason unrelated to the ledger. Two concurrent bars (warm editor plus batch, or the textcheck loop) building or running the same Release output can also collide on file locks (MSB3027) and give the same red.

**Fix.** Use a dedicated tiny project (`CommentOnly.cs` plus a `Main`) with its own output directory, or build once per run as in F5.

### F7 (LOW): stale-assembly path

`RunnerDll` is hard-coded to `../PoliSim-captures/textcheck/bin/Release/net8.0/textcheck.dll`. If `Directory.Build.props` ever moves the output, the build succeeds elsewhere and an older dll left at the old path gets run.

**Fix.** Ask the build for the path (`dotnet build ... -getProperty:TargetPath`, SDK 8+), or refuse when the dll's `LastWriteTimeUtc` is older than `CommentOnly.cs` or `Runner.cs`.

### F8 (LOW): the timeouts in TryProcess never fire

`StandardOutput.ReadToEnd()` runs before `WaitForExit(timeoutMs)`. A child that hangs, or a grandchild that inherits the stdout pipe, blocks the editor's main thread for as long as it lasts. The 300000 ms and 120000 ms timeouts are dead code. I did not reproduce a hang: a bash pipe on `dotnet build` returned promptly, so MSBuild nodes do not appear to inherit the handle.

**Fix.** Read both streams asynchronously, then `WaitForExit(timeoutMs)`, then kill on timeout.

### F9 (INFO): over-refusals, all fail-safe and all consistent with the ruling

Each of these is OWED although the compiled output is identical:

- `#pragma warning disable CS0168` gains `// why`
- a `#region` name edited
- `#if A||B` against `#if A || B`
- `#nullable enable` added (warnings only)
- `a` against `a`
- a zero-width U+200B inside an identifier
- a comment moved into a disabled branch
- any comment edit inside a `#if UNITY_EDITOR` block (disabled in the symbol-less parse, so compared as text)

The last one is the most likely to be met in practice.

## What held (ACCEPT only when the compiled output is identical)

All 38 probe cases matched their expected verdicts. My additional attacks each got the correct verdict:

- A raw string with its closing delimiter re-indented is OWED: the literal is one token that carries the indentation.
- An interpolated raw string with its closing `"""` re-indented, a content line re-indented, or spaces before a hole at line start is OWED. The `InterpolatedRawStringEndToken` text includes the newline and indentation, so the indentation is not whitespace trivia.
- `{x:0.0}` against `{x: 0.0}` is OWED: the format text is a token, and the output does differ.
- `{x,5}` against `{x, 5}` is ACCEPT, and the output is identical.
- Conflict markers are refused (CS8300).
- `a >> 1` against `a > > 1` is refused (CS1525).
- `List<List<int>>` against `List<List<int> >` is ACCEPT, and identical.
- `#define`, `#line 100` (4 against 100) and `#if false`/`#else` live-code edits are OWED.
- A NEL ending a comment on a directive line is OWED.
- A BOM added, doc comments with `<inheritdoc cref>` and `<include>` (DocumentationMode.Parse puts them into dropped structured trivia and nothing leaks), `__arglist` spacing, `u8` spacing and whitespace at the edges of disabled text are all ACCEPT, and identical.
- A `*/` inside a comment that closes early and exposes code is OWED.
- Unity-side output parsing: reasons have `\r`, `\n` and `\t` escaped by the runner, so no VERDICT line can be injected; a non-`ACCEPT` third column is OWED; a missing index gives NO VERDICT.

Residual not tested: version skew between the checker's Roslyn 4.11 and Unity's SDK 8.0.318 compiler. I know of no lexer difference for C# 9 constructs.

## What was done with each finding (the author)

- **The comparison itself held** against every lexer-level attack - the ruling's design needed no change.
- **F1 (the provenance rule skipped blank and block-comment lines, so a mark could be re-attached to a declaration): FIXED** - each marked line is compared with every line down to and including its declaration; the reader's three pairs are in the probe, owed.
- **F2 (a lossy UTF-8 decode made two different invalid bytes equal): FIXED** - the pairs are written as the files' own bytes and the runner decodes STRICT UTF-8, answering owed on invalid text; a probe case holds it.
- **F3 (a CRLF working tree against LF commits would owe a multi-line string forever): FIXED** - the runner drops a CR before an LF on both sides (the digest already ignored carriage returns); a probe case holds it, accepted. A lone CR is still refused, and the state and history passes still fail on one.
- **F4 (a caller-info parameter compiles a line or an argument's text): FIXED as a refusal** - while any file under Assets/ declares one (read with comments stripped, matched as an attribute), no change is comment-only; none does today.
- **F5 (cost): FIXED** - the runner is built once a run and verdicts are cached by the two texts' digests; the probe is one call.
- **F6 (the runner compiles unrelated editor sources under shims): STATED, not changed** - a shim break turns the cheap bar red, which fails closed; splitting the project is a later tidy.
- **F7 (a stale assembly could be run): FIXED** - an assembly older than the runner's sources is refused.
- **F8 (the timeouts could not fire): FIXED** - both streams are read asynchronously.
- **The DeadStateCheck finding the author hit on the way:** a string literal holding a block-comment opener made the source-reading checks' regex stripper swallow the code after it - the very weakness RL-1 retires, met inside RL-1's own file; the opener is now tested by characters.
