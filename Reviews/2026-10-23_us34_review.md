## What was verified, and how

- **The arithmetic (items 1-2): it holds.** I compiled `UsNight.cs` unchanged against minimal shims of the types it reads (`scratchpad/us34_review/nightprobe`). The probe ran 4,000 random nights: 800 midterms, 460 at 269-269 (staged through `FlipsToTie`), 529 with a 50-50 Senate, ME/NE districts with random winners, Senate specials, and independents among the seats not up. At the last declaration, every night's College, House (of 435) and Senate (of 100) equal the input sums. I recounted all 207,200 mid-night instants independently from the night's own order. Each call lands exactly when its line is first crossed, never before. No call ever reverses. NO MAJORITY appears only once `rep + toCome < 270 && dem + toCome < 270`, which on these inputs means only at 269-269 with nothing to come. TIED appears only at 50-50 with nothing to come. The order runs safest first. The midterm list never holds DC. Every `FlipsToTie` result that was not null came to exactly 269-269 (555 cases; 17 null, where no subset sums to the surplus). Result: **bad 0**.
- **The count has no third-party electors.** `ElectoralCollege` gives every jurisdiction's electors to a nominee, and `OthersLead` is only a flag. So `UsNight.cs:186`'s REP-else-DEM reading matches the count. A third party "winning electors" cannot happen in this model. The night never says when others led a state (L5).
- **The Senate seats are taken from the right places.** The seats up come from the contest. The seats not up come from `SeatSides(country, Convenes)` with the seats up removed, so the night's Senate is `SenateOn(Convenes)` by construction. Past the record's reach, `UsSenate.On` reads at its last day, so a 2028 or 2030 night is not left with an empty "not up" set. Independents are counted only among seats not up that the game has not elected over. The House majority is the count's seats in force over two plus one (218 of 435). The game models no vacancies, so none can move it.
- **The cartogram (item 3) is exact.** `perl Tools/dus_cartogram_prep.pl` with the decoded sources writes a file **byte-identical** to the committed `UsTileCartogram.cs`. Both source digests match `SHA256SUMS.txt` (tiles 7aa10f24..., board 674796fc...). An independent perl count of `tiles.json` gives 538 cells. Every state's cell count equals its 2024 electors in `UsPresidentialReturns.States` (ME 4 = 2 at large + districts 1-2; NE 5 = 2 + 1-3).
- **The live path (item 4) is sound.** `ElectionNightFromModel.At` returns null for the USA, and its only callers are the UI and the film. Forks are deserialized worlds (`ShadowBaseline`), so their contest lists are their own. The preview clone shares the lists but never counts. A save carries the contests (format 49), and a reload reopens no night. `CheckUsHouseChoice` runs once per stepped day. It fires only on `CountedOn` for a contingent contest whose House has voted, and `AuditDriver` dismisses `_electionNight` generically, so batch audits do not stall on it.
- **Nothing on the simulation path changed (item 6).** No file under `Assets/Scripts/Simulation` or `Persistence` changed, and the `UsPresidentialElection.cs` hunk touches only a comment. The save format is untouched. `bar_tier` still classes `Assets/Scripts/Elections/**` as simulation, so the commit owes the simulation bar with the `us24dl` sentinel. That bar has not run (M3).
- **Housekeeping is in order.** `bash Tools/cgate/gate.sh` prints GATE OK. All six new `.meta` GUIDs are unique in the tree, in the precedent's two-line form. Every changed file is LF in the index. The new `PartyInkDrawSiteCheck` entry is honest: `ElectionNightScreen.Usa.cs` draws no `Accent(`/`AccentOnDesk(`, and `UsTileView` names no ink accessor. ## Findings

### H1 - The cheap bar fails: MetaTextCheck hits a player string
`Assets/Scripts/UI/ElectionNightScreen.Usa.cs:155`: the Senate's tied slip reads `"AN EQUAL SENATE: THE VICE PRESIDENT'S VOTE DECIDES (ARTICLE I, SECTION 3)"`. MetaTextCheck's pattern `'section N'` (`\bsection \d+\b`, case-insensitive, `MetaTextCheck.cs:78`) reads every literal under `Assets/Scripts/UI`, and its allow-list has no entry for this file or for `ARTICLE`. I ran the pattern set over the new UI files with a perl probe (`scratchpad/us34_review/metaprobe.pl`), and this literal is the only hit. Scenario: the first cheap bar on this tree is red on MetaTextCheck. Fix: word the citation the way the rest of the screen does ("ART. I §3 CL. 4" would also hit the § pattern). Either reword it in prose or add an allow-list pair with its reason, following F4-2's statute precedent.

### H2 - `UsNightDiagnostic` is in no bar
`Assets/Editor/CheckSuite.cs` has no entry for it; compare `("PolishNightDiagnostic", ...)` at line 215. The class heads of `UsNight.cs` and `GameController.UsNight.cs` say "`UsNightDiagnostic` fails while any of the three differs", but nothing runs it. The branch also carries no evidence that it was ever run. Scenario: a later change to `UsCongressElection.SeatSides`, to `StatesOf`, or to the House by state makes the night disagree with the count. The bar stays green, and `ShowUsNight` logs an error only for the College and the House (L2). §901's review raised the same gap for Poland as M1, and there the integrator fixed it. It is high here because this diagnostic is the only check behind items 1, 2 and 8. Fix: register it in the cheap group, run it, and record the output.

### M1 - On a midterm with a 50-50 Senate, the slip prints "1 JAN 0001"
`ElectionNightScreen.Usa.cs:155` builds the tied-Senate slip from `DeskDay(board.TakesOffice)`. On a midterm, `GameController.UsNight.cs:26` leaves `TakesOffice = DateTime.MinValue`. Scenario: the 2026 midterm ends 50-50 (529 of the probe's 4,000 random Senates did). The chip's slip reads "THE SITTING VICE PRESIDENT TO 1 JAN 0001, THEN THE VICE PRESIDENT-ELECT", but no president or vice president is elected at a midterm. Who breaks the tie: on a presidential night the slip's own words are right (the sitting VP until noon on 20 January, then the VP-elect), but the night never names which side that leaves holding the Senate, even after the College is called. That is a choice, but the slip should say so. Fix: on a midterm, the sitting VP throughout. On a presidential night with the College called, name the incoming VP's side.

### M2 - On every midterm night, DC is drawn as not yet declared
`UsNight.cs:205` keeps only jurisdictions with House seats on a midterm. That is right for the count, but DC gets no `Jurisdiction`, so `ElectionNightScreen.Usa.cs:444` paints all three DC cells as the plate under every lens. `UsTileView` then dashes DC's outline, because `Declared` is false, and the slip says "Not counted tonight" (line 487). Scenario: at "50 OF 50 DECLARED", DC still shows dashed as "not yet". The lens note says "Dashed is not yet declared", and the Congress key's "no seat (DC)" dotted swatch never matches it. Fix: paint a jurisdiction the night does not count as dotted, with no dashed outline.
