## The questions

### 1. K109's planted clause (Gate18Diagnostic)

The old clause demanded that every list other than the planted one keeps its HANDED share. For Italy, IC and ScN are handed 0.000000: no 2018 list carries them (log lines 2051-2052). So `Based` correctly gives each its share of record, and the old clause failed on a correct rule. The new clause compares each other list with `Based(election, held.BeforeFactors)`, the unplanted base, and keeps the first half unchanged (the planted key must take exactly its share of record).

`Based` is elementwise: a key is rebased only when it is handed nothing and the record has it. So for Sweden, Germany and Poland, where every list is handed a share above zero (log: no zero among their FIT lines), the unplanted base IS the handed share. For those three countries the new clause therefore reads the same as the old one on the present code.

- **Still bites:** the realistic break, where a list handed nothing is not rebased (the rebase dropped, the wrong share, the wrong total). It fails the first half in all four countries.
- **No longer bites:** the over-reaching break, where `Based` also rebases lists handed a positive share. The new second half compares `Based` with `Based` and passes. The old clause compared with the handed share and failed. Nothing else in Gate18 goes red on that break either: the carried check is `Apply(Based(...))` against itself, and q18 is in-sample. See finding L1.

### 4. K216: CabinetBlocs, JointMasks and the generalised rule

**Other countries are unchanged.** `CabinetBlocs` returns `Array.Empty` for every country but Italy. The new loop in `JointMasks` then adds nothing, and the method returns exactly what it did (Germany: the one CDU|CSU mask or null; Sweden, Poland: null). Every caller passes the masks straight through, so their behaviour cannot change outside Italy:
- TryFormSeats;
- FormationProposal.Prepare, and through it SimulationManager.cs 4716 / 4775;
- the three diagnostics.

For Italy, the blocs are `ItalianCount.Coalitions(Camera)`: FdI+Lega+FI+NM and PD+AVS+PlusE+IC. Seatless members are left out and a bloc needs two seated members. The roster has 18 parties, far from the int mask's 31.

**The pair case, side by side (Evaluate, the joint loop).** OLD:
- walk p ascending over the mask's members;
- `if (larger < 0 || seats[p] > seats[larger]) { smaller = larger; larger = p; } else { smaller = p; }`;
- skip if either is -1, else copy larger's side, reason and oppose bit to smaller.

NEW:
- `larger` = the first p (ascending) with strictly the most seats;
- then every other member takes larger's side.

For a pair a < b:
- seats[b] > seats[a]: both give larger = b, smaller = a.
- seats[b] <= seats[a], ties included: both give larger = a (strict `>`), smaller = b.

The side, the reason string and the opposeMask update are the same three statements, so the result is identical, ties included. For a one-member mask, the old code skipped on smaller < 0 and the new inner loop finds nothing. (Pairs always have two bits by construction anyway.)

The new loop reads only larger's state, never a smaller's, so the order of the smaller members cannot matter. `JointAlike` and `SplitsJoint` were already written for masks of any size, with the same strict `>` tie rule as the new loop.

**Callers.** No other caller of the generalised rule exists: the loop is inside Evaluate and is reached only through `chamber.Joint`, whose producers are listed above. The old code was in fact wrong for a group of three or more (only the last non-larger member followed the larger). It was latent until now.
