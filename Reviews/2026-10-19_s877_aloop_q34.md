## M findings

### M1. `TaxTermPoints` reads a line's placeholder rate whether or not the line is levied, so q37 can rebuild D-32 by snapshotting it
- **Where:** ParliamentSystem.cs:692-696 (`TaxTermPoints`, documented as "levied or not"), used at :680-681. The levy's `ToPoints` is computed at :681 *before* `IsImplemented` is set at :683, so it relies on this.
- **Failure scenario:** §2 (2) of the plan has q37 snapshot "each line's effective rate" at every fiscal-year start in "the one unit". The obvious way to build that is a loop calling `TaxTermPoints` on every line. An unlevied excise line would then be snapshotted at its placeholder 8 points instead of 0.
  - A levy that q37 books from this seam (0 → 8) then disagrees with the year's net: rate now (8) minus opening (8) is 0.
  - Depending on how q37 combines the two, the levy is either charged twice or nets to zero. Netting to zero is D-32 again, this time in the approval term.
  - The struct says the line was at 0 points before the levy, but the helper says 8. The seam carries two answers to "what is this line's level".
- **Fix (cheap, now):** add `TaxLevelPoints(country, line) => line.IsImplemented ? TaxTermPoints(country, line) : 0f` as the one reader for "the line's position" (snapshot and now). Then in `ApplyTaxProgramBillResult`, take `FromPoints = TaxLevelPoints(...)` before the flip and `ToPoints = TaxLevelPoints(...)` after it. Alternatively, rename `TaxTermPoints` to `RatePoints` and state at the method that q37's snapshot must read 0 for an unlevied line.

### M2. Diagnostic (8)'s move check cannot detect a wrong unit: its expected value is computed by the function under test
- **Where:** HouseholdBurdenAnchorDiagnostic.cs:150 (`points = ParliamentSystem.TaxTermPoints(c, line)`) against :170-172 (`move.ToPoints == points` / `move.FromPoints == points`).
- **Failure scenario:** the change claims the move is "in q37's one unit (D-33): effective-rate points for every rate line, sub-rows included; the dial's per cent for a per-tonne line". (8) passes whatever `TaxTermPoints` returns, so it only shows that `Apply…` calls the helper.
  - It also runs only on the seed world. There the income line has no sub-rows, so the "sub-rows included" half is never tested.
  - If `TaxTermPoints` returned `line.Rate` for the income tax, or omitted `PointsOf` for the carbon line, (8) would still pass.
- **Fix:** add three independent expectations:
  - Sweden's income line with the GA-2-12 sub-rows set (flat layer and state band at 0). The removal's `FromPoints` must equal `TaxSchedule.EffectiveRate(c, line, line.Rate)`, and must differ from `line.Rate` by more than 1 point.
  - Germany's or France's carbon line levied at the seed. The removal's `FromPoints` must equal `line.Rate * 100 / line.MaxRate` (the per cent of the dial), not the currency rate.
  - A band move and a levy of the same effective points read the same number on the one scale (q37's own pass criterion, anchored here).

## L findings

- **L1. Diagnostic (9) skips the real load path.** HouseholdBurdenAnchorDiagnostic.cs:213-214 nulls `SeedLevied` by hand and calls `RestoreSaveState` directly. It never shows that a pre-q34 v43 **JSON** deserializes to null. That holds today (Newtonsoft, `MissingMemberHandling.Ignore`, the parameterless `Country()` at Country.cs:1068, no initializer on the field). But a later `= new List<TaxType>()` initializer would silently turn every older save into "the seed levied nothing", which reads the whole household burden as a gap, and (9) would still pass. Fix: serialize a save, strip `"SeedLevied"` from the text, then `Deserialize` + `RestoreInto`, and assert the gap is unchanged.
- **L2. Diagnostic (8) cannot tell "the seed side keeps a removed line at its SEED rate" apart from "at today's rate".** At the seed, `Rate == BaselineTaxRates[type]`. By reading, the code uses `BaselineTaxRates` (MacroSystem.cs:167), so the claim is true, but nothing pins it. Fix: move VAT's rate +2 through a budget bill, remove it, and expect the gap to equal −share at the **seed** rate.
- **L3. Older save with a removal before the save.** If such a save removed a seed tax before it was cut and the line is re-levied after the load, the re-levy reads as a rise from zero (SimulationManager.cs:5701-5705; the seed set is "levied at the load"). This is stated in SaveGameService.cs:99-103 and in the code comment as "not migrated", and the save is v43 under ruling A. It is accepted as written. Note only.
- **L4. The chamber's direction and the seam's unit disagree for the income tax.** `GetTaxProgramBillDirection` (ParliamentSystem.cs:655-656) reads `PointsOf(Rate)`, the lever, while `TaxTermPoints` reads `EffectiveRate`. This only matters for an income-tax removal, where the chamber votes on lever points and q37 will charge effective points. This is not a q34 defect; record it for D-33's re-unitting in q37.
- **L5. Tax programme bills reach no impact-ledger fork made before them (pre-existing, now wider).** Tax programme bills are not a `PlayerLeverKind` (PlayerLever.cs:12-26), and PolicyImpactLedger has no bill handling. An except-world forked before a levy carries no pending bill, so it never levies. The levy's effect was already booked to every earlier-forked family through revenue (the class of §865 M4). q34 adds the consumption channel to that misbooking. Fix: file it with the AF-11/FORK-1 family. It is not this piece's job.
- **L6. Hand-made countries changed slightly.** These have empty `BaselineTaxRates` and null `SeedLevied`. Before q34, the seed side summed `RevenueAtRate(type, 0, atStatute: true)` over today's levied lines. For a hand-made country whose income tax *responds*, that sum is only approximately zero, because Sweden's credit makes the yield at a zero lever non-linear. Now it is exactly zero. Country.cs:509-510 says "as its empty BaselineTaxRates already read", which is true to within that residue. Only Editor harnesses are affected. Note only.
- **L7. Policy scenarios now move, as intended.** SimulationTestRunner's `stress` scenario levies the wealth and carbon taxes at turn 10 and removes the estate tax at turn 20 (:733-740). `parliamentstress` forces every line on (:419). AuditDriver's X-05 levies. Their burden figures now move. This is q34's intended effect, but confirm that none of them is pinned by a digest or bar.

## Hunt items: checked and clean

1. **No-policy byte-identity.** The only runtime write to `TaxLine.IsImplemented` is ParliamentSystem.cs:683, reached only through `AdvanceTaxProgramBillsDay` (SimulationManager.cs:2257). Its bills come only from `IntroduceTaxProgramBill`, whose only runtime caller is the player's switch (GameController.BudgetV35.cs:518); every other caller is in Editor or Testing code.
   - No AI finance ministry, event, Finance partner, US docket/veto, Poland veto or "tax act split" path writes `IsImplemented`. The act split and the carry touch `BudgetBill.TaxLines` rates only.
   - Nothing adds, removes or replaces `TaxLines` after `SeedTaxLines` except the preview clone (`TaxLine.Clone` copies `IsImplemented`).
   - `BaselineTaxRates` is written only in WorldFactory (:1167, :1224-1225).
   - So in a run with no policy, `SeedLevies(t) == IsImplemented` for every line on every day. The AI changes rates only, never levies.
   - An AI rate move on a line the player removed is skipped on both sides, so it has no effect.
2. **Float identity.** Same loop over `country.TaxLines` in the same order. Same skips (the corporate tax and tariffs). Same rate source on each side (today's rate, or `BaselineTaxRates` and the PriceLevel scaling for the per-tonne line). Same `RevenueAtRate` calls with the same `atStatute`. `SeedLevies` does no float work. With equal sets the sum is bit-identical. `TaxTermPoints` runs only on a moved bill, and its `YieldNow` memo is a pure cache of the same values, so it cannot shift later readings.
3. **SeedLevied on copies.**
   - The ShadowBaseline fork, AF-12's carried world and the impact ledger's except-worlds all copy the world by a save round trip. `SeedLevied` is a public field of a `[Serializable]` class with no opt-in attributes, so Newtonsoft writes and reads it, and the copies carry an equal set.
   - The preview clone copies it as its own list (SimulationManager.cs:6724).
   - PreviewParityDiagnostic's clone audit checks presence only for reference-type fields (:340), so it passes. It does not check content, but the copy is a straight list copy.
   - The seeded no-policy shadow is built by WorldFactory, which sets it.
   - No other Country copier exists (`new Country(` appears only in WorldFactory and ClonePreviewCountry).
4. **The older-save reading in RestoreSaveState.** It sits at SimulationManager.cs:5701-5705, inside the per-country loop beside the other additive adoptions. It comes after `SetWorld` (which reads no burden: `SeedPublishedHistory`, `CommitCalendarYear`) and before the pending state and any day.
   - `RestoreInto` calls it before the campaign replay and `SeatTheRecordOnItsDate`. GameController's load reads nothing in the world before `RestoreInto` (GameController.cs:939-945).
   - A new game uses `SetWorld`, not `RestoreSaveState`, so the reading never runs there. In any case the set is non-null from WorldFactory.
   - On the forks the set is non-null, so the reading does nothing.
   - The reading is correct: the old build summed only today's levied lines on both sides. With the set equal to "levied now", every line enters both sides exactly where it did before, and a loaded old save keeps its burden to the bit.
5. **TaxTermPoints against §2 (2).**
   - A rate line uses `TaxBases.EffectiveRate`. For the income tax that is `TaxSchedule.EffectiveRate(country, line, line.Rate)`, which reads `YieldNow` with the line's live `BracketRates`, so the sub-rows are included. Every other line uses its own rate.
   - A per-tonne line uses `PointsOf(Rate)` = rate × 100 / MaxRate, the per cent of the dial.
   - That matches the plan's "effective-rate points for every rate line, the dial's per cent for a per-tonne line". `EffectiveRate` does not depend on `IsImplemented`, so computing the levy's `ToPoints` before the flip gives the line's rate (but see M1).
   - Caveat for q37: `MaxRate` moves with the price level at every boundary, so an unmoved carbon rate's points drift across a boundary inside a fiscal year.
6. **TaxLevyMove.** `Moved` is false for a failed bill (the existing approval charge is kept, and the struct is returned), for a line the country does not carry, and for a bill that finds its line already as asked. `Type` is set in every case. The one runtime caller (SimulationManager.cs:2257) discards the result, and the method is not used as a delegate or method group anywhere. The void-to-struct change alters no behaviour. No approval charge was added.
7. **Diagnostic strength.**
   - (7) compares the set against the seed world it was taken from, so it can only fail if WorldFactory flips a line after `SeedTaxLines`. That is weak, but it is the right tripwire.
   - (8) is strong on the burden. Every household line of all six countries is levied or removed, the move is checked against an independently computed revenue share with a tight tolerance and a direction check, and each bill is undone with the gap restored to 1e-7. Its two blind spots are M2 and L2.
   - (9): see L1.
