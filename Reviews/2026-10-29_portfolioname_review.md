## Findings

### HIGH

**H1. The new check will turn `CommentImmunityCheck` red: it is an unenrolled source reader.** `Assets/Editor/CommentImmunityCheck.cs:160-176` walks every top-level `Assets/Editor/*.cs`; a file is a "source reader" when its comment-stripped text matches `ReadsSource` (`File.ReadAll(Text|Lines)` or `SourceText.Read...(`, line 92) and contains the literal `"*.cs"`. `PortfolioDisplayNameCheck.cs:59` has `Directory.GetFiles("Assets/Scripts", "*.cs", ...)` and `:62` has `File.ReadAllLines(path)`, so it matches both. It is in neither `MustStrip` (`CommentImmunityCheck.cs:40-77`) nor `Exempt`, and the diff does not touch `CommentImmunityCheck.cs`. The census then adds "PortfolioDisplayNameCheck reads source and is enrolled in neither list" to its failures and exits 1; `CommentImmunityCheck` is registered in the same suite (`CheckSuite.cs:362`). The compile gate cannot see this; the bar will. (Derived by reading the census, not by running Unity.)
Fix (the right one, not the exemption): read through `SourceText.ReadWithoutComments(path)` (cache-aware, and it also removes the comment false positives in M3), split on `\n`, and add `"PortfolioDisplayNameCheck"` to `MustStrip` with a one-line reason, as `UiLeverVerbCheck` did at `CommentImmunityCheck.cs:74-75`. Caveats of the stripper to keep in mind: a multi-line `/* */` collapses to one space, so reported line numbers drift after one (report the trimmed text as the check already does, or accept the drift); and a `//` line comment that contains a quote is NOT stripped, so a comment such as `// was $"{appointment.Key}"` would still be a false positive (none exists today). Re-run `CommentImmunityCheck` after.

### LOW

**L1. The scan's line filter is not covered by the teeth.** The `Caught`/`Passed` lists (`PortfolioDisplayNameCheck.cs:25-36`) test only the regex. Nothing plants a file or a line to prove that the `$"`/`Debug.Log` filter and the directory walk would report a raw write, so a regression in the loop (say the filter inverted) would print "0 raw write(s)" and CLEAN. `UiLeverVerbCheck` plants source for its classifier. Add one planted source string pushed through the same per-line function (extract the loop body into a method taking a `string[] lines`).

**L2. Whole-line `Debug.Log` exclusion hides real writes on the same line.** `:66` skips any line containing `Debug.Log`, including `Debug.Log(...); label = $"{portfolio}";` and a trailing `// Debug.Log` comment. Today `SimulationManager.cs:7138-7139` puts the log and the ledger write on separate lines, so it is safe now; a one-line `{ Debug.Log(...); RecordEvent(..., $"... {x.Portfolio}") }` would be missed. Prefer excluding only the `$"` literal that sits inside the `Debug.Log(` call, or stating the limitation.

**L3. No existence guard.** `:59` calls `Directory.GetFiles("Assets/Scripts", ...)` relative to the current directory with no `Directory.Exists` test and no "files > 0" assertion; `UiLeverVerbCheck.cs:251` guards its walk. In batch mode the cwd is the project root so it works; run from elsewhere it throws instead of failing with a sentence. (`CheckExit.ArmLogFold` is called, so the exception would still fold into a non-zero exit.)

**L4. Reads the disk directly, bypassing the bar's source cache.** `File.ReadAllLines` (`:62`) re-reads 398 files the other source checks already hold in `SourceText`'s per-bar cache (`CheckSuite.RunTable` opens a scope). `SourceText.ReadLines` (or the H1 fix, `ReadWithoutComments`) uses the cache.

**L5. Naming.** `Effectiveness.DisplayName(...)` shares its name with the UI's static class `PoliSim.UI.DisplayName` (`DisplayName.Of`), which is the very class the method's summary tells callers to avoid; inside `PoliSim.Data` there is no clash (the gate compiled), but a reader meets `Effectiveness.DisplayName(x)` and `DisplayName.Of(x)` a few lines apart (M2 is the live example). `PortfolioName` would read unambiguously.
