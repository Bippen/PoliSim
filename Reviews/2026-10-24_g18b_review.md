## (2) The fit's definition, and what (c) actually tests

The fit uses the shares handed to the idle game's count (`held.BeforeFactors`). Nothing upstream reads the table, so the run is deterministic, at seed 777 under `NoiseAtZero`. A patched run therefore hands the count *the same* `BeforeFactors`. The fit iterates the count itself to a miss of 1e-12, and the factors travel by `{2:R}` (a round-trip format). So on the first run after the patch, (c) passes **by construction**. Poland has no staged campaign and no doors, so its count at σ 0 is the identity and the fit is exactly target ÷ handed.

**Things (c) does not test, because the fit absorbs them:** the doors' turnout movement, the vote rounding and the count's nonlinearity. All of these are inside the fixed point. Seats are not asserted at all.

**Things (c) does test that the fit does not guarantee:**
- **(i) Reachability.** A list handed 0 keeps factor 1 (`Fit`, :217 and :239) and cannot be moved, so (c) fails honestly. Germany's BSW is the likely case: a TRUE ZERO prior and previous in the 2021 pair the snap start reads (PartySystem.cs:725-726) against a record of 4.98 % (5.20 % of the roster). See M3.
- **(ii) Later drift.** After a model change, the stored factors meet new handed shares. The 1.5 pp is then a real regression tolerance.
- **(iii) Leaks.** A future change that let the table reach the campaign would move `BeforeFactors`. That shows up only as "DUE A REFIT", which is *reported*, not failed, as the prereg rules. A leak under 1.5 pp passes. See M2.

**The out-of-sample figure is honest.** It is the same count of the same `BeforeFactors` at factor one, and nothing of the record reached those shares. The pre-election epoch resolves `Seated` to 2022, 2021 and 2019 respectively, so the prior is not the result. Two limits: it is a single seed-777 draw of the run-up (`EventSystem` and others draw from `SimulationRandom`; a real game seeds from the clock), so it is not an error distribution (M6). And since 0de1c316, its seat column is allocated on base 1 while the game's is on the record's base (L1).

## Findings

### High

- **H1 (fixed in 0de1c316) - the fit pushed lists across the statutory line.**
  - At 23e1137a: `NationalElection.Allocate` read the threshold on `max(total, 1e8)` of shares summing to one (NationalElection.cs, the §704 line). Fitting to the record's share *over the roster's total* therefore moved Germany's BSW from 4.98 % of the valid vote to 5.20 % of the roster, and BSW cleared 5 %.
  - **Failure scenario:** the patched Bundestag seats BSW, which the record does not. CDU+CSU+SPD (45.0 of 91.4 seated points, about 49 %) loses the majority it had (45.0 of 86.2, about 52 %). (d) fails, or the formation forms something else, for a reason that has nothing to do with the model.
  - **The fix in 0de1c316 reads correctly:**
    - Germany: `thresholdBase = 1e8 / RosterShareOfVote`.
    - Sweden: the same base for 4 % of the votes in the whole country.
    - Poland: `Admitted(share × RosterShareOfVote)`, with MN exempt as before.
    - On every other day the base is 1, which is inert.
- **H2 (open) - the idle game is not the world a new game builds; it never seats the average cabinet** (Gate18Diagnostic.cs:140-146 against GameController.cs:2286, AF-30b J5).
  - The idle player is the PM's party in all three elections (M, SPD and PiS). That is exactly the case where `SeatAverageCabinet` fills every vacant chair of the player's ministries. Without it those ministries run below the pool's floor for the whole run-up.
  - That moves the economy, which moves the economic vote, which moves the handed shares, and the factors absorb a vacant-cabinet penalty that no real game has.
  - The class doc and the gate's doc both claim "a world built as a new game builds one", and `PlayProtocolStaging` (:81) already copies this line for the same reason.
  - **Failure scenario:** the fit ships, and a real Swedish game, with average ministers seated, hands M a different share on 13 Sep 2026. Its counted result misses the record by whatever the cabinet effect is, while the gate reports 0.00 pp.
  - **Fix:** after `country.PlayerPartyAbbrev = player`, call `CabinetSystem.SeatAverageCabinet(country)` (and set `PartyApprovalRating` for parity), *before* the first fitting run.
