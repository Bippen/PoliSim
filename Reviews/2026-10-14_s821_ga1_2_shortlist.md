**Findings**

1. **HIGH, CONFIRMED - the resumed run appoints a day late, so `c2_se_cab_r40` and `b4_se_cab_r40` cannot match their originals.**
   - **Why:**
     - On a resumed run, `Opening()` records the opening and sets the speed in the same tick, then returns (AuditDriver.cs:517-523). `Act` first runs in a later Playing tick (:574).
     - That tick runs after the controller's Update (AuditHarness.cs:221-235). With delta 0.25 at VeryFast's 0.25 s a day, one frame is one day (AuditDriver.cs:55-56; GameController.cs:321-330, :770-775).
     - So day 41 is simulated with no cabinet, and only then does `Act` search and appoint.
     - The uninterrupted run appointed in day 40's tick (AuditDriver.Styles.cs:401-408), so its day 41 ran with the cabinet.
     - The Finance minister's CompetenceBias feeds the daily fiscal flow (SimulationManager.cs:425 → :6994 → :7133).
   - **Evidence in the old logs:**
     - `area1c/c2_se_cab_r40.events.log:8-9` and `area1b/b4_se_cab_r40` both say "ACT cabinet day 41", against "day 40" in the original runs (`c2_se_cab.events.log:28-30`).
     - Both runs appointed the same Finance minister, Elena Voskresenskaya.
     - The Budget's daily step:

       | Step | Original | Resumed |
       |---|---|---|
       | Day 39→40 (no cabinet in either run) | -0.01716 | -0.01716 |
       | Day 40→41 | -0.00361 | -0.01701 |
       | Day 41→42 | -0.003458 | -0.003459 |

   - **What this means:**
     - The ledger's Budget gap on 2026-02-28 (-0.8072551 against -0.8206597) is caused by the one-day lag, not by the shortlist.
     - The shortlist's own effect is the three different appointees: Bruno Castellano, Otto Baumgartner and Yuki Dahlberg against Amara Osei-Bonsu, Wei-Lin Tanaka and Tobias Marchetti.
   - **What the running recheck will show:** COMPARE DIFFERENT on D 2026-02-28, "Budget: -0.8072551 against -0.8206597" - the same numbers as the ledger. The day-41 rows of both runs are unchanged by the patch. At the same time the events logs should show "Search drew shortlists for 0 portfolio(s)" and the same six names.
   - **Fix:**
     - In the resumed branch of `Opening`, don't set the speed. Keep a pending speed and apply it in Playing after `Act(c)` on the first tick (or call the cabinet block before `SetSpeed`), so the start day's acts land before day startday+1 runs.
     - Then re-run the area1b and area1c cabinet pairs.
     - Update the "Expected" line in p4_ga1_2.plan to match. Judge GA-1-2 by the zero-portfolio Search and the matching appointee names.
     - Note in the GA-1-2 ledger row that its Budget figure comes from the lag.

4. **LOW, PLAUSIBLE (latent) - live and resumed games hold different kinds of minister object.**
   - `GenerateCandidates` hands out the static pool's own objects (CabinetSystem.cs:525) and `ApplyAttributes` writes to them in place. So an uninterrupted game seats objects shared across the whole process, while a resumed game seats deserialized copies.
   - The values are identical today. But any future in-place change to a seated minister - for example a popularity drift, or Editor reflection writes like LeverLivenessCheck.cs:566-567 - would land on the shared object in one game and not in the other, which is the GA-1-2 class of bug again.
   - Fix: have `GenerateCandidates` return a fresh `CabinetMinister` per draw, with the authored attributes applied to the copy.
